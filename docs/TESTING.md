# Проверка релиза

## Что подтверждено для v0.2.0

- Сборка с опубликованного тега прошла для обоих ASI. Состав архивов, SHA-256 трёх файлов релиза и все записи `BUILD-INFO.txt` сверены с GitHub и локальными файлами.
- Игра запущена на отдельной копии с обоими ASI и загрузчиком из опубликованного игрового ZIP. Direct3D подтвердил полноэкранный режим **1920×1080 при 240 Гц** и **MSAA 8×**.
- На предыдущей локальной сборке HP2WSFix 2.5 проверены `Desktop`, ручной режим `Config` при 1280×720 и восстановление 1920×1080 при отрицательной высоте. В каждом случае проверена запись размеров в обе секции `rendercaps.ini`.
- Полный заезд, расположение всех элементов HUD и откат опубликованного ZIP v0.2.0 ещё не подтверждены. Ниже приведены сценарии для этих проверок.

## Замер микрорывков

1. Временно задайте `SampleSeconds=5` и `FrameTraceSeconds=90` в `scripts/HP2Display.ini` и перезапустите игру.
2. Проедьте первую одиночную гонку 90 секунд без Esc. Запишите время каждого заметного рывка по таймеру гонки, трассу, MSAA, частоту дисплея и включённую интерполяцию.
3. Дождитесь строки `Frame trace: saved`. Затем изучите CSV из `scripts`. `elapsed_ms` отсчитывается с начала записи, `frame_ms` измеряет интервалы между окончанием Present, `present_ms` — время внутри вызова, `previous_log_ms` — накладные расходы записи обычного лога. Колонки `tick`, `race_view`, `camera_blended`, `player_blended` и `cars_blended` помогают сравнить рендер с симуляцией.
4. Сопоставьте пики с замеченными рывками и проверьте, повторяется ли интервал. Промежутки между Present не измеряют время фактического вывода кадра монитором. Для сравнения проведите второй заезд по той же трассе с одним изменённым параметром.
5. Верните `SampleSeconds=0` и `FrameTraceSeconds=0`.

В рабочем заезде 27 ноября 2026 года (1920×1080, 240 Гц, MSAA 8×) за 90 секунд записано 19 585 кадров. Медиана интервалов — 4,29 мс, 99-й процентиль — 8,19 мс, максимум — 11,30 мс. Период 5–7 секунд не подтвердился. На отрезке около 17–19 секунд записи встречался интервал между наблюдаемыми тиками до 56 мс. Обычный лог не совпал с длиннейшими интервалами кадров в предыдущем контрольном замере.

## Сравнение тестовой сборки

- Для камеры оставьте `Camera=1` и повторите несколько поворотов камеры назад, возвращений и смен ракурса при одинаковом FPS. Сравните `SyncCameraCuts=0` с `1`. В CSV поле `camera_cut_sync` отмечает кадры, где камера и машины переведены на один и тот же шаг.
- Для ограничителя оставьте те же разрешение, развёртку и MSAA. При `VSync=0` прогоните `FrameLimit=60`, `120` и `240` и сравните медиану, 99-й процентиль и длинные интервалы `frame_ms`. `pacing_wait_ms` показывает ожидание до Present, `present_ms` — время внутри Present. Сравнивайте одинаковые участки трассы с сопоставимой нагрузкой.

В локальном заезде с VSync лимит 120 FPS выровнял интервалы Present, при этом водитель всё ещё замечал рывки. В отдельном заезде с PresentMon при 240 Гц рывки не проявились. Причину ранее отмеченных рывков пока не установили.
