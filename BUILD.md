# Сборка и выпуск

## Инструменты

Нужны Windows, PowerShell, Visual Studio Build Tools с компонентом C++ x86/x64, Windows 10 или 11 SDK с x86-библиотеками, Git и Python 3.10+ для упаковки. Скрипт находит MSVC через `vswhere` и выбирает новейшие установленные x86-инструменты и SDK. Плагин использует C++17 и статическую C/C++ runtime.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\HP2Display\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\HP2WSFix\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\HP2Display\build.ps1 -Verify -GameRoot "D:\Games\HP2"
```

Первая команда собирает единый `out/HP2Display.asi` с HP2WSFix 2.5. Вторая собирает отдельный HP2WSFix для сравнения с v0.2.0. `d3d8.dll` берётся в готовом виде из `third_party/Ultimate-ASI-Loader/`. Тесты HP2Display используют определённый по SHA-256 EXE и `d3d8.dll` из `-GameRoot`. Стенд работает с временной копией обёртки и использует полноэкранный режим 1920×1080. Закройте игру перед запуском стенда.

## Установка тестовой сборки с одним ASI

На отдельной копии игры переместите старые `HP2Display.asi` и `HP2WSFix.asi` за пределы папки игры. Скопируйте в `scripts` новый `out/HP2Display.asi`. Для настроек используются прежние `HP2Display.ini` и `HP2WSFix.ini`. При чистой установке возьмите оба файла из `config/`. Строка `HP2WSFix: integrated` в `HP2Display.log` подтверждает работу встроенного широкоформатного модуля. Если в `scripts` остался `HP2WSFix.asi`, HP2Display оставляет широкоформатные правки отдельному модулю.

Для отката закройте игру и верните оба файла v0.2.0. Если режим `Desktop` перезаписал ручные размеры, восстановите сохранённый `rendercaps.ini`.

### Смена камеры и лимит FPS

В тестовом `scripts/HP2Display.ini` ключ `[Interpolation] SyncCameraCuts=1` удерживает машины и камеру на текущем шаге симуляции при резкой смене вида. Значение `0` возвращает прежнее поведение. Параметр действует при `Camera=1`.

`[Display] FrameLimit=0` выключает программное ограничение. Положительное число до 1000 задаёт лимит FPS. В журнале `limit_fps` показывает выбранный лимит, а `actual=… Hz` показывает режим монитора. Для проверки самого ограничителя используйте `VSync=0`, чтобы ожидание развёртки не влияло на сравнение. После изменения конфигурации перезапустите игру.

### Разрешение отражений кузова

В `[Graphics]` файла `scripts/HP2Display.ini` ключ `ReflectionSize` задаёт размер текстур отражения. Доступны `256`, `512` и `1024`. При отказе выделения плагин пробует меньшие размеры. `ReflectionSize=0` возвращает штатные 128×128. После изменения перезапустите игру и проверьте строку `Reflections` в `scripts/HP2Display.log`. Например, `requested=512 selected=512 verified_targets=7/7` означает, что все семь пар текстур и буферов глубины созданы в запрошенном размере.

## Пакет из тега

Для выпуска одного ASI используйте сценарий из соответствующего тега. Например, после создания тега `v0.3.0-rc.1` выполните:

```powershell
python .\package_release.py v0.3.0-rc.1
```

Скрипт получает дерево тега через `git archive`, собирает единый ASI и проверяет SHA-256 загрузчика. В `dist/` появляются игровой ZIP, его файл `.sha256` и архив исходников. `BUILD-INFO.txt` в игровом ZIP содержит тег, полный хеш коммита и контрольную сумму каждого файла пакета. Версии компилятора и SDK могут влиять на SHA-256 собранного ASI.

Перед публикацией проверьте архив по [матрице тестов](docs/TESTING.md). В GitHub Releases приложите игровой ZIP, файл `.sha256` и ZIP исходников. Описание берётся из [CHANGELOG.md](CHANGELOG.md). Руководство для внешней площадки хранится в `docs/STEAM-GUIDE.md`. Для v0.1.0 и v0.2.0 используйте сценарии упаковки из их тегов.
